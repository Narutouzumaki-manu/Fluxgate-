### Pytest markers
`slow`, `perf`, `live` (hits real providers — never in CI by default), `security`, `property`.

### Global test rules
1. **No real secrets/PII in fixtures.** Use canaries: `AKIAIOSFODNN7EXAMPLE`, `ghp_` + 36 `A`s, `gsk_` + synthetic, fake `user@example.com`; Aadhaar/PAN generated by test helpers (valid checksum, non-real); card numbers from public test ranges.
2. **Time is injected** (`FakeClock`). No `sleep` in unit tests.
3. **Randomness is seeded** (`hypothesis` database committed for regressions; `random.Random(seed)` elsewhere).
4. **Determinism for the embedding model:** same text → same vector (assert cosine ≥ 0.9999 between runs).
5. **Network off by default:** `pytest-socket` or equivalent; `live` tests opt in.

## 2. Member 1 — Standalone Testing of `guardrails/` + `cache/` (Phase 2)

Member 1 must be able to prove correctness **without** `gateway/`, `router/`, or `dashboard/` existing. Tools: unit/property tests, CLIs, `verify_m1.py`, and the `FakeRouter` (in `shared/testing/`) when a simulated upstream is needed.

### 2.1 Guardrails — test matrix

| Area | Test type | Must-have cases |
|---|---|---|
| **Normalization** | unit + property | NFKC folding; zero-width/bidi stripping; **idempotence** (`normalize(normalize(x)) == normalize(x)`); homoglyph fold; decode-probe bounded (depth ≤ 2, size cap) |
| **Email/phone** | golden sets | plain, plus-addressing, subdomains; `+91 98xxxxxxxx`, `098…`, spaces/hyphens; no match on order IDs/timestamps |
| **Aadhaar** | golden + property | valid **Verhoeff** 12-digit with/without spaces/hyphens → detected; same shape with bad checksum → *low-confidence/ignored per policy*; leading digit 0/1 rejected |
| **PAN** | golden | pattern `AAAAA9999A` with valid 4th-letter holder-type set; lowercase variants; embedded in sentences; ignore random 10-char IDs |
| **Credit card** | golden | Luhn-valid 13–19 digits with separators; Luhn-invalid ignored |
| **Secrets** | canary + corpus | each provider format (`AKIA…`, `ghp_…`, `gsk_…`, `sk-or-v1-…`, `nvapi-…`, `sk-…`, `fgx-…`, JWT, PEM header/body), Bearer headers, `key=value` assignments; **entropy heuristic** with allowlist for UUIDs, git SHAs, hashes, base64 images |
| **False-positive corpus** | corpus | 500+ benign snippets (code, logs, docs about security, UUIDs, SHA-256 strings, version strings, phone-like invoice numbers). Report FPR per detector |
| **Redactor + vault** | property | **round-trip:** `restore(redact(x)) == x` for any generated text with PII; placeholder collisions impossible even if user text contains placeholder-looking strings; overlapping span merge deterministic |
| **Injection rules** | corpus + unit | per-rule positive/negative pair; categories: instruction override, role/DAN jailbreak, system-prompt extraction, delimiter/format tricks (`</system>`, fake tool results), encoded payloads, markdown-image/URL exfiltration, multilingual variants (English + Hindi transliteration sample); threshold behavior at warn/block boundaries |
| **Indirect injection** | corpus | benign document with an embedded "ignore all prior instructions…" paragraph, HTML comments, hidden Unicode, instructions to call tools/exfiltrate; benign documents that *discuss* prompt injection (must not block at default policy) |
| **Decision logic** | table-driven | (risk, PII types, policy) → decision/redactions matrix; `on_internal_error` strict vs permissive; oversize input path |
| **ReDoS safety** | adversarial | every regex run against 1 MB adversarial strings (long repeats, nested quantifier bait): finish < 250 ms; CI fails on regression |
| **Response scanner** | unit | secrets/PII in model output redacted; placeholder restoration only where policy allows |
| **Log hygiene** | canary | run full engine with canary secrets and `caplog`; assert none appear in log output or exception messages |

### 2.2 Stream redactor — the critical property tests

**Invariant 1 (split invariance):** for any text `T` and any partition of `T` into chunks `c1..cn`, `concat(feed(ci)) + flush().text` is **identical** to the one-shot result of redacting `T`.

```python
# test sketch (spec, not implementation)
@given(text=texts_with_canaries(), cuts=sorted_cut_points())
def test_split_invariance(text, cuts):
    one_shot = redact_whole(text)
    r = new_stream_redactor()
    out = "".join(r.feed(c) for c in split(text, cuts)) + r.flush().text
    assert out == one_shot
```

**Invariant 2 (no leak):** a canary secret split at *every* possible boundary (including 1-char chunks) never appears in the concatenated emitted output.

**Invariant 3 (bounded latency):** the redactor never withholds more than `W` characters; text not near a potential match is emitted immediately (assert emitted length ≥ len(fed) − W after each feed).

**Invariant 4 (placeholder restore across chunks):** `⟦FG:EMAIL:1⟧` split across chunks is restored exactly once when policy allows restoration; never partially emitted.

**Edge cases:** multi-byte Unicode at chunk boundaries (chunking operates on decoded strings, adapter handles UTF-8 boundaries); empty chunks; flush with a dangling partial prefix (emit as-is if it is not a full match); two secrets adjacent; secret at stream start/end; very long single chunk (> W).

### 2.3 Cache — test matrix

| Area | Test type | Must-have cases |
|---|---|---|
| **Canonicalization/keys** | unit + property | key stable under JSON key order, whitespace-insensitive where defined; **changes** when model, temperature, top_p, max_tokens, stop, seed, tools, response_format, system prompt, or any message changes; `stream` **ignored**; `fluxgate` options excluded from the key except `cache_scope` |
| **L1** | unit | hit/miss, LRU eviction, SQLite fallback, TTL expiry (FakeClock), policy_version bump invalidates |
| **L2 threshold** | unit | similarity 0.93 → hit; 0.91 → miss with `near_miss_similarity`; boundary exactly 0.92 behavior defined (`>` strict) |
| **Compat fingerprint** | unit | same query, different system prompt / context hash / model / tools / params → MISS with `compat_mismatch` populated |
| **Tenant isolation (security-critical)** | **hypothesis stateful test** | random interleavings of store/lookup/invalidate across N tenants: a lookup for tenant A **never** returns an entry stored by tenant B, via L1 or L2, even with identical text and identical embeddings; per-tenant index files/objects are distinct; `cache_scope` partitions further |
| **Eligibility** | table-driven | each `CacheBypassReason` produced by its trigger: tools, `n>1`, high temperature, multimodal, non-`stop` finish, incomplete stream, PII redacted, WARN decision, risk above threshold, unclean response, too large |
| **Poisoning defenses** | adversarial | (1) response containing injection-like instructions is not stored; (2) a blocked/warned request never writes; (3) attacker stores entry for a query then victim in same tenant with near-identical query only gets hit if compat matches; (4) entry re-scanned on read when `policy_version` changed; (5) oversize/garbled embeddings rejected; (6) per-tenant quota and eviction prevent flooding |
| **TTL sweeper** | FakeClock | expired entries removed from SQLite **and** FAISS (IDs removed), index rebuild consistency |
| **Persistence** | integration | restart: indexes rebuild from `cache_entries` embeddings; hit behavior unchanged |
| **Concurrency** | asyncio | 200 concurrent lookups/stores; no exceptions, no cross-tenant results, store idempotent for duplicate `exact_key` |
| **Embedding service** | unit | shape (384,), norm 1, determinism, memo LRU, thread-pool bounded, truncation at 256 word-pieces documented and tested (long text still returns vector) |

### 2.4 Standalone CLIs (Member 1's manual verification, also used live on Discord)

```bash
# Guardrails
python -m guardrails.cli check   "text or @file.txt"  [--policy strict] [--json]
python -m guardrails.cli redact  "text or @file.txt"  [--restore]
python -m guardrails.cli stream-sim "text" --chunk-size 1|3|random --seed 7   # feeds StreamRedactor, prints emitted vs expected
python -m guardrails.cli scan-context @chunks.jsonl                               # indirect-injection scan

# Cache
python -m cache.cli store    --tenant t1 --prompt "…" --response "…"
python -m cache.cli lookup   --tenant t1 --prompt "…"          # prints outcome, similarity, near-miss, timings
python -m cache.cli lookup   --tenant t2 --prompt "…"          # must MISS (isolation)
python -m cache.cli stats    --tenant t1
python -m cache.cli sweep                                        # TTL sweep
python -m cache.cli threshold-sweep --pairs @pairs.jsonl --from 0.80 --to 0.98 --step 0.01
```

## 3. Member 2 — Testing `gateway/`, `router/`, `dashboard/` (Phase 3)

Member 2 starts from Member 1's merged code and tests with the **real** engines. Provider network access is mocked unless a test is marked `live`.

### 3.1 Router and adapters

| Area | Cases |
|---|---|
| **Adapters (respx + golden fixtures)** | success; usage mapping; parameter pruning for unsupported params; header requirements (OpenRouter attribution); OpenRouter **200-with-error-body**; 400 pass-through; 401 (provider key invalid → provider disabled + alert, not retried); 429 with/without `Retry-After`; 5xx; read timeout; connect error; malformed JSON; SSE with comments/keep-alives; SSE ending without `[DONE]` |
| **Circuit breaker (FakeClock)** | CLOSED→OPEN at threshold; OPEN rejects instantly (`CIRCUIT_OPEN`); after recovery window → HALF_OPEN with limited probes; probe success → CLOSED; probe failure → OPEN with reset timer; 429s handled as cooldown not necessarily trip (per TRD); concurrent callers during HALF_OPEN only N probes pass |
| **Selector** | priority order; skip open breakers; model alias per provider; all open → `fluxgate_no_healthy_provider` |
| **Retry safety** | retries only before first byte delivered; never after streaming started; respects overall deadline; jittered backoff bounds; no retry on 4xx client errors |
| **Chaos scenarios** | provider A returns 429 for 60 s; A flaps; A hangs (timeout); A mid-stream disconnect; all providers fail → clean 503 |

### 3.2 Gateway

| Area | Cases |
|---|---|
| **Auth/keys** | key creation returns raw key once; DB contains only HMAC hash + prefix; wrong/revoked key; constant-time compare; key never appears in logs/traces (canary) |
| **Rate limiter** | burst then refill; per-key independence; `Retry-After` accuracy; cache hits still count per RPM policy |
| **OpenAI compatibility** | official `openai` SDK (sync, async) pointed via `base_url`; non-stream; stream (`stream=True`, with and without `stream_options.include_usage`); `/v1/models`; error envelope shapes parsed by SDK into proper exceptions; unknown extra params pass through; `fluxgate` body field stripped before upstream (assert via mock upstream capture) |
| **Pipeline order** | L1 before guardrails (ADR-01); L2 after (ADR-02); BLOCK → no upstream call; redaction → provider receives placeholders only (assert on mock upstream capture); response restored per policy |
| **Streaming** | SSE framing (`data: …\n\n`, `[DONE]`); first-byte latency; tee-and-store on complete streams; **no store on client disconnect / upstream error / missing `[DONE]`**; stream cache hit replays valid SSE; redaction of canary split across upstream chunks; backpressure with slow client |
| **Failover end-to-end** | A failing → B serves; headers show provider; trace lists attempts |
| **Telemetry** | every request yields exactly one trace; audit event per finding; queue overflow policy (drop-oldest + counter, never block request path); shutdown drains |
| **Cross-tenant (HTTP level)** | two keys/two tenants send the same prompt: second tenant gets MISS and its own upstream call |
| **Dashboard** | each of the 4 views renders with seeded data, empty DB, and error state; no external network requests (CSP header assertions); playground endpoints return expected decisions; key creation shows raw key once then never again |

### 3.3 Integration tests with the real M1 engines (`tests/integration/`)
Run the full ASGI app in-process (httpx `ASGITransport`) with `mock_upstream` (deterministic provider with configurable latency/failures). These double as Phase 4 overhead benchmarks' functional baseline.

### 3.4 Performance smoke (Member 2)
`locust` or a simple async load script: 50 concurrent clients, 60 s, mixed hit/miss. Record error rate, p50/p95/p99, memory growth (must be flat). Not a benchmark claim — a regression guard.

## 4. Contract Tests (Shared, CI-enforced)

1. **Schema snapshot:** `model_json_schema()` for every contract vs committed JSON snapshot.
2. **Protocol conformance suite** parameterized over `[Fake*, Real*]` implementations: identical behavior on canonical scenarios (clean request, PII request, block request, L1 hit, L2 hit, tenant miss).

## 5. Benchmark Methodology (Phase 4)

### 5.1 Setup requirements
- Record: CPU model, cores, RAM, OS, Python version, library lockfile hash, **commit SHA**, config (threshold, TTL, policy), provider/model IDs, date/time.
- Warm-up: 20 requests discarded; model loaded; indexes built.
- Repetitions: ≥ 5 runs per scenario; report median of run medians and min/max; keep raw per-request CSV/JSON.
- Seeds fixed; workloads committed.
- Network variance: real-provider numbers are **indicative**, report with variance; overhead claims come from the **mock upstream** with fixed injected latency.

### 5.2 Workloads

| ID | Name | Composition | Purpose |
|---|---|---|---|
| W1 | **Repeat-heavy** | 500 requests drawn from 100 unique prompts with a Zipf(s≈1.1) distribution | L1 hit rate, token/latency savings |
| W2 | **Paraphrase-heavy** | 100 base questions × 4 paraphrases (LLM-generated, human-spot-checked 25%) | L2 hit rate vs **false-hit rate** |
| W3 | **Adversarial near-duplicates** | PAWS-style pairs (high lexical overlap, different meaning) + negation flips + changed numbers/entities | L2 false-hit rate at threshold |
| W4 | **Unique** | 300 distinct prompts, no repeats | Worst-case FluxGate overhead |
| W5 | **RAG with context** | Hybrid RAG questions with retrieved chunks; same question + same chunks vs same question + different chunks | Compat-fingerprint safety; real-world savings |
| W6 | **Security corpus** | injection prompts (direct), poisoned documents (indirect), PII/secret-laden prompts, benign hard negatives | Detection recall/precision/FPR; redaction correctness |
| W7 | **Failover chaos** | W4-like traffic while provider A is forced to 429/5xx/timeout in phases | Failover success, added latency |
| W8 | **Streaming** | W1/W4 with `stream=true` | TTFT overhead, stream cache replay, redaction latency |

### 5.3 Scenarios (before / after)

| Scenario | Path |
|---|---|
| **Baseline-A** | Hybrid RAG → provider directly |
| **FluxGate-off** | Hybrid RAG → FluxGate with cache disabled, guardrails permissive (measures pure proxy overhead) |
| **FluxGate-guard** | + guardrails only |
| **FluxGate-full** | + L1 + L2 cache, strict policy |

### 5.4 Metrics and formulas

| Metric | Definition |
|---|---|
| Latency p50/p95/p99 | client-observed end-to-end; TTFT for streaming |
| **Proxy overhead** | `latency(FluxGate-off, mock upstream) − latency(direct to mock)` p50/p95 |
| L1 hit rate | `L1_hits / total_requests` |
| L2 hit rate | `L2_hits / (requests that missed L1 and were L2-eligible)` |
| Overall hit rate | `(L1+L2 hits) / total_requests` |
| **L2 false-hit rate** | fraction of L2 hits whose cached answer is judged **not equivalent** for the new query (labelled sample ≥ 200 hits; labelling rubric + inter-rater check between the two members; optional LLM-judge cross-check disclosed) |
| Cache lookup latency | L1 / L2 p50/p95 from `StageTimings` |
| **Tokens saved** | sum of `usage.total_tokens` of the *original* cached response for each hit (provider-reported usage; `tiktoken` fallback flagged as estimate) |
| **Cost saved (est.)** | `tokens_saved × price table` (price table file committed; "estimate") |
| Quota saved | provider calls avoided = hits |
| Failover success | `requests answered successfully during provider fault / total requests during fault` |
| Failover added latency | median extra latency on failed-over requests |
| Injection detection | precision, recall, F1 on attack corpus at warn and block thresholds; **FPR on benign corpus**; per-category breakdown |
| PII/secret redaction | recall and precision per type; leakage count (raw canary present in upstream-captured payload) must be **0** |
| Stream redaction | leakage under 1-char/random chunking = 0; added per-chunk latency |
| Memory | RSS at idle, after 50k cache entries |

### 5.5 Reporting and claim policy

- Output: `integration/benchmarks/reports/results/<date>_<sha>_<scenario>.json` + `REPORT.md` aggregating them with charts.
- **Targets vs Measured table** (copied from PRD) is filled with `Measured ✅ / ❌ / Not measured`. A missed target is reported as missed with the reason; it is not edited out.
- README/resume text may only use numbers present in `REPORT.md`, written like: *"On a 4-core laptop CPU (see REPORT.md), median proxy overhead was X ms (n=…)"* — never "achieves" or "guarantees".
- Prompt-injection results are stated as **"detected N% of a K-sample corpus with M% false positives on benign set"**, never as protection guarantees; corpus composition is described and limitations listed.

### 5.6 Hybrid RAG integration rules
- The RAG project is a **client only**: change its OpenAI `base_url` and API key; optional `extra_body={"fluxgate": {...}}` for `retrieved_context` and `semantic_query`.
- FluxGate repo has **no** import of or dependency on the RAG code. The adapter lives in `integration/benchmarks/rag_client_adapter.py` and invokes RAG through its public entry point or an HTTP call, configured by path/URL.
- For W5, freeze the RAG index and retrieval parameters so identical queries produce identical chunks; log chunk IDs to compute `context_fingerprint`.
- Plant poisoned documents in a **separate test corpus** (never the user's real documents).
- Provide a baseline run of RAG without FluxGate in the same session to cancel provider drift.

### 5.7 Threshold tuning procedure (L2 default)
1. Build labelled pairs from W2 (should-hit) and W3 (should-miss).
2. `cache.cli threshold-sweep` from 0.80 → 0.98.
3. Plot hit rate vs false-hit rate; choose the lowest threshold with false-hit rate ≤ 1% (target) on W3; compare to the initial `0.92`.
4. Record decision in `docs/DECISIONS.md`; the default changes only via a PR containing the sweep results.
